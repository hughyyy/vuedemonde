# Changelog

All notable changes to vuedemonde are recorded here, per the quality-work
convention: **every component fix lands with its own commit, a changelog
entry, and an update to `docs/quality-audit.md`**.

## Unreleased — default theme expansion

### Changed
- **Per-component catalogue** (replaces the tier-2 upgrade path): the release
  renderer now emits **one composite image per exported component (106)** —
  each a 2×3 grid of six themes (`dark`/`thermal`/`bubblegum` over
  `light`/`sunshine`/`mint`) as WebP at `docs/assets/components/`. Demos live in
  `playground/src/catalogue/` (generated registry from `catalogue-meta.json`);
  the README tables are regenerated by `scripts/catalogue-readme.mjs`.
  `?print=component&id=&theme=` renders one demo with the theme on `<html>` so
  teleported overlay panels inherit it. New parity test
  (`test/catalogue-registry.test.ts` — registry must equal the four barrels)
  and a per-demo render audit (`audit/catalogue-audit.test.ts` — every demo
  mounts clean under all six themes).

### Added
- 8 new shipped themes (16 → 24, an even 12 dark / 12 light split): **Amethyst**
  (deep violet dark) plus seven lights — **Sakura** (blush pink), **Lavender**
  (pale violet), **Lagoon** (cool aqua teal), **Citron** (olive light), **Clay**
  (terracotta), **Gilt** (antique gold) and **High Contrast Light** (the
  white/black counterpart of High Contrast). Every one sits inside the shipped
  contrast envelope (validator-clean; no new errors), and each light theme is
  the deliberate counterpart of an existing or new dark theme — see the banner
  layout in `BannerPrint.vue` for the pairings.
- Theme banner (`?print=banner`) re-curated to **two rows of 12** — every dark
  theme in the first row, every light theme in the second, each column pairing a
  dark theme above its light counterpart. The banner page and both screenshot
  harnesses widen to 2120 px so all 12 cards fit per row.

### Fixed
- Terminal ANSI palette: the component decided light-mode by matching the theme
  id `"light"`, so `mint`, `sunshine`, `pure-platinum`, `monotone` and every
  other light theme rendered with the dark ANSI palette. Polarity is now read
  from the resolved `--bg` luminance (same ≥ 0.35 boundary the theme builder
  uses). Regression test in `test/terminal.test.ts`.

### Docs (proposals — not implemented)
- `docs/per-component-rendering.md` — spec for replacing the 27 family catalogue
  images with one image per component, each showing six themes
  (dark/thermal/bubblegum + light/sunshine/mint). Records the blocking
  constraint (teleported overlay panels escape `data-theme` islands, so a
  composite must stitch six separate browser passes, not six in-page islands),
  the proposed `?print=component` route + demo registry, the image-weight budget
  (PNG ≈ 32 MB vs WebP-q65 ≈ 10 MB), and the open questions.
- `docs/github-pages.md` — feasibility study for hosting the playground and
  theme builder on GitHub Pages. Verified against a real build served under
  `/vuedemonde/`: the static build runs, all routes work, theme-builder
  `#spec=` share links decode, there are no server dependencies and no
  path-based routing (so no `404.html` fallback needed). The only config change
  required is Vite `base`.

## 0.2.1 — quality focus phase (released 2026-10-22 — first publish to npm as `vuedemonde`)

Beginning of the QA pass over the full component inventory: every component is
audited for rendering errors, accessibility and edge states. Fixes commit
individually; regression coverage lives in the opt-in render-audit suite
(`npm run test:audit`) — it mounts every family section and every theme and
fails on any console error/warning. It is not part of the default `npm test`,
so it runs on demand rather than on every change.

### Changed
- Project renamed `vuedemond` → `vuedemonde`: package name, folder/repo, the
  `@vuedemonde` path alias, dist artefact names (`vuedemonde.js` /
  `vuedemonde.css`), the `vuedemonde-ripple` keyframes, and the playground's
  persisted theme key. User-facing branding is set as **Vue de monde**.
- Every theme block now declares `color-scheme` (`light` for `light`,
  `pure-platinum`, `mint`, `sunshine`, `monotone`; `dark` otherwise) so native
  controls, scrollbars and form widgets match the palette instead of staying
  light on dark themes. Generated blocks did this already; the ship list did not.

### Added
- Render-audit suite (`audit/`, `vitest.audit.config.ts`): mounts all nine
  family sections (print mode) under dark/light/thermal + the theme banner
  under all 16 themes; asserts zero console errors/warnings.
- Vision-gated visual regression harness (`scripts/visual-regression.mjs`,
  `visual-compare.mjs`): re-renders the catalogue surface (9 families × 3
  themes × base/hover/focus states + 16-theme banner + app shell = 77
  deterministic frames) and compares each frame to the previous render via
  a two-stage gate — a 112-bit fingerprint (gradient dHash + color
  signature) first, a full pixel diff with change bbox only on mismatch,
  and only genuinely changed frames surface for vision-model analysis
  (magenta overlays + cropped vision-ready artifacts + `results.json`).
  Determinism is enforced: frozen page clock (calendar seeds/"today"/timers
  cannot drift), mouse reset between shots (no stale `:hover` inheritance),
  stubbed remote images, reduced motion, fixed viewport. Commands:
  `npm run visual:capture|test|update|report`. Design + triage protocol:
  `docs/visual-regression.md`.
- `AGENTS.md` — repo conventions for agent work (commands, test style,
  quality process, visual-harness invariants); `docs/handover.md` — phase
  handover with the open register and flagged edge cases.
- `docs/quality-audit.md` — the living issue register for the phase.
- Theme builder (`/?build` in the playground): pick 13 anchor colours, derive
  the other 21 tokens, unlock any derived value, preview on the real kit, and
  export the block as a selectable theme (`[data-theme]` + registration), a
  fixed `:root` theme, or a default `:root:not([data-theme])` theme. Contrast is
  reported against the shipped themes' envelope; state is shareable via URL.
  Core model in `playground/src/builder/theme-spec.ts`, documented in
  `docs/theme-builder.md`, round-trip tested against all 16 shipped blocks.

### Fixed
- Theme builder preview (playground): the pane put the cards on `--bg` and showed
  `--canvas-bg` as a 40 px strip, so editing the canvas colour repainted almost
  nothing. It is now an app shell — `bg` page, `surface-1` top bar/sidebar,
  `canvas-bg` work area with the cards nested on it, plus a scrim + dialog
  specimen for `--overlay`, rich text on `canvas-bg`, and explicit
  `--link`/`--reasoning` swatches (no kit component consumes those two).
- Theme builder share links: `decodeSpec` accepted `{id, anchors}` with anchors
  missing, and a missing anchor reached `parseHex(undefined)` and blanked the
  page. Every anchor is now required and validity-checked, unknown overrides are
  dropped, missing knobs default, and the hash tracks later edits instead of
  restoring a stale draft.
- Theme builder editing: picking a colour for `overlay` / `*-soft` no longer
  drops the token's alpha (a 14 % tint used to become a solid fill); invalid hex
  text reverts instead of reaching the emitted CSS; ids are normalised and
  empty/shipped-clashing ids are reported; lock buttons carry an `aria-label`
  instead of announcing "◇".
- `test/theme-icons.test.ts`: the expected theme-id list is parsed from
  `theme.css` instead of duplicated, so the stylesheet and `THEME_IDS` cannot
  drift (the builder's registration step relies on this).
- App.vue (print harness): dialog left-aligned in print so the open drawer never covers it.
- InputsSection (playground): print-mode panel opens now pin scroll to top — teleported panels (DatePicker/CascadeSelect) were anchored against a scrolled viewport, floating ~620px off their triggers (caught by the per-card visual audit).
- Fieldset: collapse toggle wired to its body (aria-controls).
- CalendarToolbar: view switcher is a proper tablist (role=tab + aria-selected).
- Charts (Bar/Line/Donut/Radar): charts take an optional ariaLabel for assistive tech.
- DataTable: sortable headers are real buttons with aria-sort; selectable rows keyboard-operable with aria-selected.
- Tree: items expose aria-level/aria-disabled; selectable rows keyboard-operable.
- AppAccordion: headers wired to their panels (aria-controls per item).
- Menubar / MegaMenu / TieredMenu: triggers announce popup type and open state (aria-haspopup + aria-expanded).
- Carousel: labelled carousel region semantics (role=region, aria-roledescription).
- AppTooltip: bubble hidden from assistive tech until shown; wired via aria-describedby.
- BlockUI: blocked content becomes inert (no keyboard escape into it).
- ConfirmPopup: panel announced as a labelled dialog.
- Popover: new label prop — named dialog panel.
- FileUpload: drop zone keyboard-operable; native file input inert (tabindex -1).
- AutoComplete: full combobox contract — named input, aria-expanded/controls, arrow navigation with aria-activedescendant, Escape.
- DatePicker / CascadeSelect: trigger buttons announce their expanded state (aria-expanded).
- InputOtp: group labelled "One-time code"; each digit named distinctly (Digit N of M).
- InputTags: tag input keeps an accessible name (ariaLabel, default "Add tag") even when tags clear the placeholder.
- InputPassword: field named (ariaLabel default "Password"); reveal toggle pressed-state; dead icon ternary removed.
- InputColor: current-colour button labelled; hidden native picker out of tab order and AT.
- Listbox: full keyboard navigation (arrows skip disabled, Home/End, Enter/Space pick, aria-activedescendant).
- FloatLabel / IftaLabel: slotted label wired to the slotted input (for/id) on mount.
- Slider: degenerate min===max range no longer renders NaN fill.
- Knob: same degenerate-range guard on the arc.
- Compare: divider is keyboard-operable (focusable, arrow keys, focus ring) — parity with Splitter.
- AppInput: hint/error text wired to the control via aria-describedby; aria-invalid omitted when clean; token focus-visible ring.
- AppTextarea: same describedby/aria-invalid/focus-ring contract as AppInput.
- AppSelect: same describedby/aria-invalid/focus-ring contract.
- AppRadio: per-instance radio group name (useId) — multiple groups no longer cancel each other's selection.
- PaneSection: toggle wired with aria-controls (useId) and a focus ring.
- AppProgress: aria-valuenow clamped to 0–100 like the bar; indeterminate/spinner animation stops under reduced motion.
- AppMessage: errors announce as role=alert (others stay status); close button gets a focus ring.
- AppChip: removable close button gets a focus ring.
- Skeleton: text-line mode hidden from assistive tech (aria-hidden).
- AppButton: aria-label/aria-busy for icon-only and loading states, focus-visible ring, spinner stops under reduced motion.
- InputsSection (playground): the Knob demo referenced the component without
  importing it, so it silently never rendered in the catalogue — caught by the
  first audit run.
- Terminal ANSI parser: runs now snapshot their style at write time. SGR
  resets that mutate in place (`22`/`23`/`24`/`27`/`39`/`49`) previously
  rewrote already-committed runs retroactively and merged adjacent runs of
  different styles — `\x1b[1mbold\x1b[22mnormal` rendered fully unstyled.
  Found by the new edge-case matrix (multi-parameter SGR, selective resets,
  cursor/erase sequences, clock-stamped lines).
- `v-mask`: typed slots now skip (drop) characters that do not fit the slot
  instead of freezing on them, and `X` advances the stream — a stray letter
  in a numeric field no longer blocks every later slot (`1a2b3` with
  `###` now yields `123`, and `XX-XX` with `a1b2` yields `a1-b2`).
- Tree: the first expand click on a default-closed node did nothing (the
  fold-set only recorded explicit folds, so toggling a closed-by-default node
  marked it folded again instead of opening it). Expansion overrides are now
  an explicit open/closed map, so a manual toggle flips the CURRENT state —
  first-click expand works, and a folded node stays folded under `expandAll`.
- TreeItem: row clicks no longer emit `select` in non-selectable trees (the
  row was already unfocusable and keyboard-gated; the click path is gated to
  match).
- MonthCalendar: a crowded day's "+N more" overflow could be expanded but
  never collapsed; the toggle now becomes a "show less" button.
- CascadeSelect: the trigger never reflected a bound `modelValue` — the
  selection only appeared after picking inside the panel. An immediate watch
  now syncs the selected path from the prop (unknown ids fall back to the
  placeholder instead of crashing).
- TreeSelect: the panel's Tree was rendered without `selectable`, so row
  clicks never emitted select — picking a node was impossible.
- TreeItem / TreeRow: nodes marked `disabled` (aria-disabled + style) were
  still selectable via click/Enter/Space; all three paths are now gated.
- TreeTable: same first-expand no-op as Tree — a fold-only set could never
  open a default-closed parent. Expansion overrides are now an explicit
  Map, mirroring Tree.
- TreeRow: row clicks emitted select even with `selectable=false`; the click
  is gated like TreeItem's, and disabled rows carry `is-disabled`.
